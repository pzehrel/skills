# EasyEDA 验证循环

进行任何实时编辑、原理图到 PCB 交接、审计或签核时，读取本参考文档。

## 修改前

1. 验证 bridge 健康状态和活动 EasyEDA 窗口、项目、文档及文档类型。
2. 读取受影响的元件、图元、引脚或焊盘、网络、几何和规则。
3. 捕获领域基线：
   - 原理图：导出网表、明确的 NC 状态、引脚到网络映射、封装和 DRC/检查摘要。
   - PCB：焊盘到网络映射、元件与布线几何、未布线状态、铺铜、规则和 DRC 摘要。
4. 记录实际位号和图元 ID。进行视觉重构时，将受影响的拓扑作为权威基线。

## 修改期间

- 每次使用新的 API 操作前，读取准确的 `easyeda-api` 签名、类型、单位、枚举和备注。
- 每次只执行一个完整批次，并回读 EasyEDA 实际创建的内容。
- 将超时、connector 断开或缺少回读的成功响应视为未知写入状态。重试前先检查。
- 删除或替换后，检查所有受影响的图元类型是否有残留。
- 一个完整且已验证的批次如果重建成本较高，应在完成后保存。

## 原理图门槛

再次导出网表并验证：

- 每个已修改引脚都位于预期网络上或被明确标记为 NC。
- 目标网络准确增加预期引脚；源网络准确移除已迁移引脚；无关网络未发生变化。
- 没有预期网络被合并或拆分，没有导体使用冲突标签，也没有重复标记、孤立端口、悬空或零长度导线、陈旧旧网络短线。
- 位号、真实器件、符号功能、封装以及裸露或机械引脚仍然正确。

再次运行 DRC 和结构检查。网表证明电气归属；画布只判断可读性。

## PCB 门槛

再次读取受影响的 PCB 数据并验证：

- 焊盘、走线、过孔、铺铜和元件保留预期的网络与几何。
- 已布线和未布线连接只按预期发生变化。
- 板框、禁布区、元件间距、层使用、铜皮状态和设计规则仍然有效。
- 布线变化后，如有要求，已重建或刷新铜皮。
- DRC 没有无法解释的阻断性违规。

保存并重新读取关键状态，避免将瞬态内存结果误认为已持久化设计数据。

## 原理图到 PCB 交接

- 同步前比较原理图符号到封装的分配和连接器引脚表。
- 审查拟议变更集；不得盲目接受删除、封装替换或网络重映射。
- 同步后，将元件数量、位号、封装、焊盘和网络归属与已批准的原理图意图比较。
- 继续布局或布线前，重新运行 PCB 连接和 DRC 检查。

## 签核报告

报告已检查的项目和文档、已修改的图元或网络、已验证的接口映射、门槛与 DRC 结果、保存检查点、有意例外、剩余警告以及所有未验证项。关键差异仍存在时，不得宣称原理图、PCB 或制造准备完成。
